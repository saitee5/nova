# NOVA Data Provenance & Traceability Convention

**Status:** Locked  
**Enforcement:** Mandatory across all datasets, ML assessments, episodes, and memory vectors.

---

## 1. Provenance Classifications

Every data packet, telemetry reading, synthetic scenario, ML model artifact, and memory embedding ingested into NOVA must be tagged with one of the following canonical provenance categories:

```text
┌──────────────────────────┬────────────────────────────────────────────────────────────────────────┐
│ Classification           │ Definition & Permitted Usage                                           │
├──────────────────────────┼────────────────────────────────────────────────────────────────────────┤
│ REAL_INDUSTRIAL_DATA     │ Telemetry, alarms, or logs sourced directly from operational plant     │
│                          │ DCS, historians, or SCADA systems under strict NDA/license.            │
│                          │ High sensitivity, strictly guarded.                                    │
├──────────────────────────┼────────────────────────────────────────────────────────────────────────┤
│ SIMULATED_BENCHMARK      │ Established industry academic benchmarks, such as Tennessee Eastman    │
│                          │ Process (Downs & Vogel), Damadics valve benchmark, or open simulators. │
├──────────────────────────┼────────────────────────────────────────────────────────────────────────┤
│ PUBLIC_KNOWLEDGE         │ Publicly accessible engineering standards, API 560, API 521, OSHA,    │
│                          │ research papers, published equipment datasheets, and incident reports. │
├──────────────────────────┼────────────────────────────────────────────────────────────────────────┤
│ SYNTHETIC_NOVA_DATA      │ Correlated synthetic telemetry generated by NOVA's internal simulator   │
│                          │ (`data_simulator/`), used for scenario stress-testing and CI pipelines.│
└──────────────────────────┴────────────────────────────────────────────────────────────────────────┘
```

---

## 2. Provenance Object Schema

In domain models and JSON payloads, provenance is represented as:

```json
{
  "source": "SIMULATED_BENCHMARK",
  "dataset_id": "TEP-Rieth-2017",
  "dataset_hash": "sha256:e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "timestamp": "2026-09-12T03:50:00Z",
  "pipeline_stage": "feature_extraction"
}
```

---

## 3. Propagation Through System Layers

1. **Ingestion:** Telemetry pipelines inject provenance at the boundary.
2. **Plant State:** `PlantState.provenance` records whether the state is derived from live plant streams or simulation.
3. **ML Assessment:** Every `MLAssessment.provenance` captures the model version and training dataset hash.
4. **Operational Episode:** Recorded with origin tag in `operational_episodes.provenance`.
5. **Qdrant Vectors:** Payload metadata includes `provenance` field, enabling filtered retrieval by data source.
